## Description field markdown help

Use the **description** field to explain what the definition does, why it exists, and when to use it.

### Valid content

- Plain text is always valid.
- Multi-line descriptions are supported.
- You can use lightweight Markdown formatting.

### Supported markdown patterns

- `**bold**` for emphasis.
- `` `inline code` `` for short code, commands, or identifiers.
- Triple backticks for code blocks, for example:

    ```yaml
    name: Example definition
    version: 1.0.0
    ```

### Writing tips

- Start with a one-line summary.
- Add a short paragraph that explains expected usage.
- Include examples for paths, file types, or prompts when useful.
- Keep the wording specific so teammates understand intent quickly.
